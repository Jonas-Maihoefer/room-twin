# OpenUSD foundation for Issue B

Issue A adds three independent, read-only interfaces under `backend/app/usd/`:

- `load_roomplan_scan(room_json, metadata_json=None)` returns a `RoomPlanScan`. `furniture` is a tuple of `ScanElement` values with a parsed `UUID`, lowercase category key, string attributes, three dimensions, the original flattened column-major 16-number transform, and optional parent/confidence. `architecture` maps `walls`, `doors`, `windows`, `openings` and `floors` to equivalent elements. Units and up axis are normalized to `metres` and `Y`; `reference_origin_transform` is retained separately. Do not compose it or `parent_identifier` into element transforms without evidence. The opaque `coreModel` is ignored.
- `read_usdz_inventory(room_usdz)` returns a `SceneInventory` without extracting or changing the USDZ. `references` contains one record per referenced source layer (not one record per shared category group), with stable package layer ID, asset path, category, source prim paths, any UUIDs from prim `customData`, source-layer transforms, and composed scene prim paths/transforms. `furniture_layers` and `architectural_layers` are convenient category partitions. `layer_identifiers` excludes OpenUSD's ephemeral session layer.
- `AssetCatalog.load()` validates the backend-owned `backend/assets/catalog.json`, all contained paths and USD layers. `match(category, attributes)` returns `CatalogMatch` with `specific`, `category_default` or `missing` status. It makes no placement/scaling decision.

The source fixture inventory has 17 authored USD layers (the `room.usdz` root plus 16 references), eight furniture references with UUIDs, and eight architectural references: four walls, two doors, one window and one floor. The USDZ reports Y-up and 1 metre per stage unit.

The backend catalog copies all 42 `.rooms.usdc` source files into `backend/assets/models/`: 23 chair, 12 table, 6 sofa and 1 shelf file. Its 42 mappings preserve Apple's attribute combinations and category defaults, including repeated source filenames where Apple reused one model for several combinations. Storage/cabinet and bed have no model; the sample's `.empty` markers are not copied as models. All copied assets currently report Y-up and metres-per-unit 1.0 when opened with OpenUSD. The semantic pivot and visual fit have not been independently validated. Each manifest entry says to defer scaling until a later stage checks bounds and authored units.

Run `python -m pytest` from `backend/`. Tests import OpenUSD directly and open the real USDZ and every catalog model; they do not skip if OpenUSD is missing. CI uses CPython 3.12 on Linux. Windows development uses CPython 3.12 x86-64. The local integration run for Issue A was executed on Windows with CPython 3.14 because 3.12 was unavailable there; `usd-core==26.11` installed and the full suite passed on that interpreter. CI remains the Python 3.12 supported-runtime check.
